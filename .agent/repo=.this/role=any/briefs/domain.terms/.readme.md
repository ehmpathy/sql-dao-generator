# domain.terms — the glossary of this repo's vocabulary

one cluster per **word** that composes a domain object or domain operation this repo declares.
a word is itemized once and reused across every declaration that holds it — the verb `define`
serves `defineDaoCodeFilesForDomainObject`, `defineQuerySelectExpressionForSqlSchemaProperty`,
and every other `define*`.

## the rules that rule this dir

- `rule.require.domain-term-itemization` — every constituent term of a declared dobj/dop is
  itemized here
- `rule.forbid.domain-term-synonyms` — a contract uses the canonical word, or opens a dispute
- `rule.require.persist-domain-term-evidence` — the discovery behind a term choice lives here,
  not in a lost session
- `template.domain-term.md` — the `choice._.` cluster shape
- `howto.domain-term-disputes.[guide].md` — the dispute pattern

## the shape

```
term=<x>._.choice._.md              # say-level — chosen word, kind, forbidden synonyms, refs
term=<x>._.choice.reason.md         # ref-level — etymology, disputes, evidence (required)
term=<x>._.choice.example=<abc>.md  # ref-level — one per notable example (optional)
```

## what is out of scope

- generic english that is not part of this domain's vocabulary (`file`, `path`, `content`)
- vocabulary imported from a dependency — `DomainEntity`, `DomainObjectMetadata`,
  `HasMetadata`, `IsoPriceWords` are those packages' terms, not this repo's
- a word that appears only in prose or a comment, never in a declared name
