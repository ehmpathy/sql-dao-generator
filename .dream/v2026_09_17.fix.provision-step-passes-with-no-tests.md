# 🌙 dream: guard the provision step against a silent zero-file match

- kind  = fix
- owner = `ehmpathy/sql-dao-generator`
- caught = 2026-09-17
- status = open · no live defect

## .the cue that fired
a self-review scanned the test commands for silent credential bypasses and found a precondition
whose only guard is the absence of a flag.

## .the gap, precisely
- `test:unit` and `test:integration` each run `test:integration:provision-generated-files-to-import`
  first, under `set -eu`
- that step is a jest run whose `testMatch` names **one file**:
  `**/src/domain.operations/commands/generate.test.ts` (`jest.provision.config.ts`)
- that test regenerates the fixture that `daoCasts.behavior.test.ts` imports

today an empty match exits non-zero, because the step carries no `--passWithNoTests`. but the outer
commands do carry it, so an edit for consistency would silently disarm the guard. then a moved
`generate.test.ts` → the step exits 0 with no regeneration → the behavior suite grades a stale
fixture and reports green.

## .the shape of the fix
a clamp that bites where a flag's absence does not: the step asserts it ran exactly the expected
suite (a count check on the jest json output), or a behavior-suite case compares one generated
file against the current definer — red whenever regeneration was skipped.

## .why it is not done in this round
SAFE — test-only. not CLEAN — its subject is the build pipeline, not the runtime-types defect, and
there is no live defect to repair.
