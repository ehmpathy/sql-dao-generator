## .the cue that fired
peer review r008 nitpick.1 (`behavior-intent-coverage`): the elementwise claim is disclosed but
unverified; once `sql-schema-generator` supports native arrays, an end-to-end assertion should prove
raw `Date[]` and nested `string[]` converge on one runtime shape.

## .the gap, precisely
| edgecase | claim | proven where |
| --- | --- | --- |
| `Date[]` (`timestamptz[]`) | cast elementwise — raw `Date[]`, json `string[]` | codegen + unit only |
| `number[]` (`numeric[]`) | cast elementwise | codegen + unit only |

each half is proven alone:
- the generated shape — `getOneCastExpressionForProperty.test.ts` pins
  `dbObject.latitudes.map(asFromDatabase.number)`
- the cast — `daoCasts.behavior.test.ts` runs the generated module on both input forms

unproven: that they meet correctly on real postgres output.

## .the shape of the fix
the recipe and trigger live in
`.behavior/v2026_07_20.consume-primitive-array-classification/handoff.sql-schema-generator.md`.
this dream adds:

1. declare the array property on a **nested domain literal**, or only the raw path is exercised
2. assert with the two-read shape `generate.integration.test.ts` uses for scalars — raw select, then
   the hydrated view's `json_build_object` — both land on one runtime type, elementwise
3. assert `[]`, never `null`, for an empty native array (`COALESCE(..., '[]'::json)`)

## .why it is not done in this round
the fixture cannot be built: `sql-schema-generator`'s `ARRAY_OF` accepts only `REFERENCE` and
`UUID` (`defineProperty.ts:367`). `nativeArrays/SurfSpot.ts` records this and sits outside the cli
glob.

**un-defer trigger:** `sql-schema-generator` ships an `ARRAY_OF` that accepts primitive and enum
elements. until then the two rows are correct by construction and unproven by execution.
