# 🌙 dream: narrow the cast's input type for an UN-NESTED domain literal

- kind  = fix
- owner = `ehmpathy/sql-dao-generator`
- caught = 2026-09-11
- status = open · fulcrum `F9`

## .the cue that fired
`defineDbObjectShapesForCastMethod` declares a `...Jsoned` shape and an `...Output` union for every
domain literal. a literal that no parent nests can never arrive as json.

## .the gap, precisely
the definer branches on `extends === DOMAIN_LITERAL` — *"may this be nested?"*, never *"is it?"*.
an un-nested literal gets:

| artifact | what is wrong |
| --- | --- |
| an exported `...OutputJsoned` | names a shape no query produces |
| an `AsJsonFromDbObject` import | imported to define that shape |
| a union arm on the cast's `dbObject` | a looser contract than the truth |

harmless at runtime — no value takes the arm. the cost is a contract that claims more than it must.

## .the shape of the fix
1. ask the inbound question: scan `allSqlSchemaRelationships` for a `DIRECT_BY_NESTING` reference
   whose `of.name` is this dobj. `getAllNestedDomainObjectNames` across every relationship, unioned,
   yields the set
2. thread `allSqlSchemaRelationships` from `defineDaoCodeFilesForDomainObject` through
   `defineDaoUtilCastMethodCodeForDomainObject` into the shape definer
3. absent from the set → the entity shape: `...Strict` only
4. `rhx git.repo.test --what unit` with no `--resnap`: zero churn expected, since all four fixture
   literals (`Price`, `InvoiceLineItem`, `Certificate`, `Geocode`) are nested

🟡 check the release state first. `...OutputJsoned` is exported from a dao consumers import; once
released, its removal is a break. `sql-code-generator#95` may make the narrow free.

## .why it is not done in this round
SAFE — zero generated bytes change. not CLEAN — a parameter threaded through two definer signatures
and every test that builds their inputs.
