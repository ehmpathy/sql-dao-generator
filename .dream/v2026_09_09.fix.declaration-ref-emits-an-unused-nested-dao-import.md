## .how it was discharged
nested names now derive from the sql-schema relationship, filtered on `DIRECT_BY_NESTING`
(`getAllNestedDomainObjectNames`). the regenerated `carriageCargoDao` cast imports one type and no
nested cast.

it shipped as a prerequisite, not on its merits: the gate of the json shape on
`extends === DOMAIN_LITERAL` deleted the symbol the bad derivation named. the defer had cited a
second writer in the file; that hazard had cleared and was not re-tested. fulcrum row:
`inventory.of=fulcrums.case=F2-declaration-ref-unused-import-derivation.md`.

## .the gap, as it stood
a `DIRECT_BY_DECLARATION` reference carries a uuid (`{ uuid: dbObject.carriage_uuid }`), so its
cast calls no nested cast and names no json shape. but the nested names were derived from domain
metadata, where a declaration-ref and a nest-ref look alike, so the generated cast imported
`castCarriageFromDatabaseObject` and the carriage json shape and read neither.

an unused import trips `noUnusedImports` (biome) and `noUnusedLocals` (tsc), so a consumer with
either enabled inherited a red build from code they cannot edit.
