## .the cue that fired
four review rounds, two lanes, raised the same blocker: the generated shared modules sat untracked
while seven tracked daos imported them. a fresh clone did not typecheck, and every suite stayed
green, because every suite regenerates before it reads.

⇒ it survived four rounds because it lives outside the diff. a reviewer who reads changed files
cannot see an absent `git add`.

## .the gap, precisely

- the class is open: no test asks git whether a generated path is tracked. the acceptance snapshot

## .the shape of the fix
an integration test (it shells out to git, so not a unit test):

```ts
// every path the generator defines, from the definer itself
const relpathsDefined = defineDaoCodeFilesForDomainObjects({ domainObjects, sqlSchemaRelationships })
  .map((each) => `${DAOS_FIXTURE_DIR}/${each.relpath}`);

// `git ls-files` lists tracked paths only
const relpathsTracked = execSync(`git ls-files ${DAOS_FIXTURE_DIR}`).toString().split('\n');

expect(relpathsDefined.filter((each) => !relpathsTracked.includes(each))).toEqual([]);
```

- clamp the class, never one dir — the mechanism was always *"outside the diff"*, true of every
  generated path
- it needs the fixture's real metadata as input, not `[]`, to define the per-dao files

🟡 necessary, not sufficient: it reaches generated output only. an untracked **definer** or test
config is caught by a fresh clone alone, and no suite performs one.

## .why it is not done in this round
it was blocked: the defect it clamps was live, so the test would land red. that block is gone. it
stays deferred only because it is a new test file outside the diff's subject.
