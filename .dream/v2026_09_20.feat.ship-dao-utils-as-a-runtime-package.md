# 🌙 dream: ship the generated cast runtime as a package the daos import

- kind  = feat
- owner = `ehmpathy/sql-dao-generator` (+ a new package, unnamed)
- caught = 2026-09-20
- status = open · downstream of fulcrum `F12`, reserved for the council

## .the cue that fired
the wisher asked whether this generator already ships a bundle the cast runtime could join, so it
would not land in every consumer's repo. the pattern exists; the vehicle does not.

## .the gap, precisely

### 1. a generated dao already imports seven runtime packages
`type-fns` · `visualogic` · `helpful-errors` · `domain-objects` · `procedure-fns` · `yesql` · `pg`

verify: `rhx grepsafe --pattern "^import .* from '[a-z@]" --glob '*.ts' --path src/domain.operations/.test.assets/exampleProject/src/access/daos`

and `declapract-typescript-ehmpathy` mandates six of the seven as runtime `dependencies`. ⇒ an eighth
is one more row in a list the org already writes, not a new class of cost.

🟡 the seventh, `procedure-fns`, no practice declares — every dao `index.ts` imports it and it
resolves by npm hoist alone. a strict resolver (pnpm, yarn pnp) breaks on it. a separate small defect.

### 2. there is no bundle to join
`package.json` `main` = `dist/contract/index.js`, a file the build never produces. this package is
cli-only. so the move mints a runtime export surface or a second package.

### 3. `sql-code-generator` is refused as the vehicle
- it is a `devDependency` by org practice, so `npm ci --omit=dev` drops it
- it too publishes no runtime surface — only a cli
- wrong owner: it reads sql text and writes types; it never touches a runtime value

## .the shape of the fix
a new package in `dependencies`, added to the `persist-with-rds` practice beside `pg` and `yesql`.
its source is real `.ts`. the `defineDaoCastsSection*` definers and `defineDaoCastsCodeFile` are
deleted; each generated cast imports from the package rather than `../.generated/casts`.

- **`npm update` propagation** — the defect class most likely to need a fast fix gets the fastest
  path, rather than a regenerate in every consumer
- **the template-string blind spot closes** — double-escaped regexes become source tsc and eslint
  grade; `v2026_09_13.fix.utils-runtime-authored-as-real-source-not-template-string.md` retires
- **the generated module leaves every consumer's tree**

🟡 `F12b`: `setDbTypeParsers` is a different concern — it probes `node-postgres`' process-global
registry and reads no domain metadata. the honest shape is likely two packages: the casts, and the
parser guard.

## .why it is not done in this round
SAFE — byte-neutral at the cast contract. not CLEAN — a new published package, deleted definers,
every snapshot re-cut. and the wish's scope is this repo; no stone asks for a package.
