# 🌙 dream: author the cast runtime as real source, read and re-emitted

- kind  = fix
- owner = `ehmpathy/sql-dao-generator`
- caught = 2026-09-13
- status = open · contingent on fulcrum `F12`

## .the cue that fired
the cast definers hold dense runtime logic — a dozen-plus guards and several double-escaped regexes
(`\\d{4}`, `\\.\\d+`) — inside template literals, where tsc and eslint read them as strings.

## .the gap, precisely
drop one backslash and the template does not error: `\d` is no recognized escape, so it collapses to
`d`, and the generated regex matches the literal text `dddd`. only a regenerate-then-test run
catches it, and only where a test hits that arm.

the regexes live in `defineDaoCastsSectionAsDateFromDbValue.ts` and
`defineDaoCastsSectionAsNumberFromDbValue.ts`; each carries a `.note` that names the hazard.

🟡 a hazard for future growth, not a live defect: `daoCasts.behavior.test.ts` pins every arm today.

## .the shape of the fix
a definer that reads a real `.ts` source file and re-emits it. the file a human edits becomes the
file the compiler checks. only the cast sections qualify — they interpolate no schema data; every
other generated file does.

🔴 the source must survive the build — copied into `dist/` or inlined at compile time. that is a
build-config change.

## .why it waits on F12
F12 asks whether the casts should ship as a runtime package rather than generated code
(`v2026_09_20.feat.ship-dao-utils-as-a-runtime-package.md`):

| F12 rules… | this dream |
| --- | --- |
| a package | retired — package source is compiler-checked already |
| keep generated | the cheapest repair; take it next |

⇒ to take it first risks a re-home that a second re-home undoes.
