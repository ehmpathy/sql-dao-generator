# 🌙 dream: a nullable `string[]` is asserted `as string[]`, which is untrue when it arrives null

- kind  = fix
- owner = `ehmpathy/sql-dao-generator`
- caught = 2026-09-09
- status = ✅ discharged within the same route

## .how it was discharged
the non-reference primitive `string[]` arm now short-circuits a nullable property to `null` before
the `as string[]` assertion. `defineDaoUtilCastMethodCodeForDomainObject.test.ts` pins the guarded
form present and the unguarded form absent.

the `_uuids` reference arm (`getOneCastExpressionForProperty.ts`, `IMPLICIT_BY_UUID`) keeps its bare
`as string[]`, and that is correct: its select is
`COALESCE(array_agg(...), array[]::uuid[])`, so it arrives `[]`, never `NULL`. every arm either
guards the null or proves it cannot arrive.

## .the gap, as it stood
the arm never read `sqlSchemaProperty.isNullable`, so a nullable `string[]` passed `null` through
under a non-null assertion. no crash, and no wrong value — a wrong **type**, which is the class the
wish names: *"the generated types match what actually arrives at runtime."*

## .the cue that fired
a review caught the cast arm's absent null guard. its neighbour eleven lines above had the same
asymmetry, unnamed by the report. ⇒ once one arm skips a null check, every arm beside it is suspect.
