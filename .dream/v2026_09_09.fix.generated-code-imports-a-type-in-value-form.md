- kind  = fix
- owner = `ehmpathy/sql-dao-generator`
- caught 2026-09-09, on route `v2026_08_02.fix-truthful-runtime-types`, stone `5.1.execution.from_vision`

## .the cue that fired
a conventions self-review asked whether the code we **generate** follows our conventions where it
lands. this repo's source uses `import type` for type-only imports; its output does not. the
route's own `AsJsonFromDbObject` import was fixed in-round; this is the extant half.

## .the gap, precisely
```ts
// every generated castFromDatabaseObject.ts, findById.ts, findByUnique.ts, upsert.ts …
import { HasMetadata } from 'type-fns';
```

- `HasMetadata` is `export type` (`type-fns/dist/checks/hasMetadata.d.ts:26`)
- `sedreplace --mode plan` measured 67 matches across 67 fixture files
- under `verbatimModuleSyntax: true`, a value-form import of a type raises **TS1484**, so a
  consumer with a modern tsconfig cannot compile our output
- this repo cannot see it: its `tsconfig.json` sets `importsNotUsedAsValues: "remove"`, which
  rules out `verbatimModuleSyntax`, so `--what types` stays green here

🟡 TS1484 is read from the spec, not executed here. one `tsc --verbatimModuleSyntax --noEmit` pass
over the example project's generated dir settles it.

⇒ the same class as the pg type-parser defect this route removed: generated code that works only
under an unstated assumption about the consumer's environment.

## .the shape of the fix
1. locate the definers: `rhx grepsafe --pattern "from 'type-fns'" --path src/domain.operations/define`
2. `import { HasMetadata }` → `import type { HasMetadata }` in each template
3. regenerate the example project
4. update every snapshot that pins the line
5. add a clamp: the generated output compiles under `verbatimModuleSyntax`. without it, the next
   type-only import reopens the gap
6. audit the other type-only imports — `SqlQueryFind*Output` from `.generated/types` is next

## .why it is not done in this round
SAFE — `import type` elides identically under this repo's config. not CLEAN — 67 files, the
definers, each snapshot that pins the line, and a new clamp, all on extant output this route did not
touch. fulcrum **F5**.
