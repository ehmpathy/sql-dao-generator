# 🌙 dream: drop the credential gates from test suites that touch no aws

- kind  = fix
- owner = `ehmpathy/sql-dao-generator`
- caught = 2026-09-20
- status = open · a scope call the human owns

## .the cue that fired
a snapshot re-cut halted on `ehmpathy.test.AWS_PROFILE: locked 🔒`. the unlock needs an sso browser
login, so every acceptance snapshot change here is human-gated — and the suite touches no aws.

## .the gap, precisely
- `declapract.use.yml` declares `useCase: npm-package` and no `awsAccountId`
- `jest.acceptance.env.ts` reads that, and its aws guard skips — correctly
- its keyrack source runs `mode: 'strict'`, and halts on a union of three manifests:

| key | source | escape hatch |
| --- | --- | --- |
| `AWS_PROFILE` | `.agent/keyrack.yml` — this repo's `env.test` | `is-optional-if-has: CI` |
| `FIREWORKS_API_KEY` | `repo=ehmpathy/role=mechanic` — its `env.test` | none |
| `AWS_PROFILE` | `repo=ghlitch/role=observer` + `role=operator` — their `env.all` | `is-optional-if-has: AWS_ACCESS_KEY_ID` |

⇒ `env.test: null` here is not enough: the `env.all` rows are unreachable from any `env.test` edit.

none of these keys appears in `src/` (checked 2026-09-24). the suite `exec`s the built cli against a
temp project and reads the files back — no sdk, no network.

🟡 integration is gated too, by a different layer. `jest.integration.env.ts` sources keyrack
`lenient`, so jest alone runs green locked; the halt is `git.repo.test`'s own strict unlock, with no
flag to skip it.

## .the shape of the fix
a scope decision across the four manifests — which roles' test keys this repo inherits — then:
`node ./node_modules/jest/bin/jest.js -c ./jest.acceptance.config.ts --forceExit` green with the
keyrack locked.

## .why it is not done in this round
UNSAFE — a credential manifest is a security surface. a wrong cut fails silently: a suite that later
needs a key gets `undefined` rather than a loud halt. and it is outside this route's subject.

⚠️ refuse the shortcut `CI=true`. it forges the environment, and it turns on jest's `--ci`, which
refuses to write new snapshots.
