# vision: sql-dao-generator — consume primitive-array + enum-array classification

## the change

the generator's one array branch treats every array as an array of domain objects and throws for the
rest, so a `string[]` is rejected. the element type already carries the answer — `property.of.type` —
and `domain-objects-metadata` classifies it three ways, mutually exclusive by construction (each guard
derives from one `getArrayElementKind`):

| guard | element `of.type` | emitted | before |
| --- | --- | --- | --- |
| `isReferenceArrayProperty` | `REFERENCE` | relation / foreign keys | relation (unchanged) |
| `isEnumArrayProperty` | `ENUM` | `prop.ARRAY_OF(prop.ENUM([...]))` → native `enum[]` | `UserInputError` |
| `isPrimitiveArrayProperty` | `STRING \| NUMBER \| BOOLEAN \| DATE` | `prop.ARRAY_OF(prop.<primitive>())` → `text[]`, `numeric[]`, … | `UserInputError` |

`photo_uuids: string[]` keeps `prop.ARRAY_OF(prop.UUID())`. a consumer stops the downgrade
(`tags: string; // todo: revert`) and models `string[]` truthfully.

the element map mirrors the extant solo map: `STRING→VARCHAR`, `NUMBER→NUMERIC`, `BOOLEAN→BOOLEAN`,
`DATE→TIMESTAMPTZ`.

```ts
if (isReferenceArrayProperty(domainObjectProperty)) { /* prior relation logic */ }
if (isEnumArrayProperty(domainObjectProperty))
  return `prop.ARRAY_OF(prop.ENUM([${options.map((o) => `'${o}'`).join(', ')}]))`;
if (isPrimitiveArrayProperty(domainObjectProperty))
  return `prop.ARRAY_OF(prop.${propForPrimitive(domainObjectProperty.of.type)}())`;
```

the contract: hydrated `DomainObjectMetadata` in (via `introspect`, which this repo already calls in
`extractDomainObjectMetadatasFromConfigCriteria.ts:15`); a `prop.*` per property plus the matched
cast and find-by code out. hydration is what makes an enum array's element `ENUM`, not `REFERENCE`.

## the rename, and the audit it forces

the metadata package no longer exposes two names this repo imports:

- `isDomainObjectArrayProperty` → `isReferenceArrayProperty`
- `isDomainObjectReferenceProperty` → `isReferenceProperty`

the old array guard was also used as a stand-in for *"any array"* at the `_uuids` sites. a `_uuids`
string array is primitive, so a blind rename there would silently drop it. the audit is per call
expression, since two files hold both kinds:

| # | file:line | target | kind |
| - | --- | --- | --- |
| 1 | `defineSqlSchemaGeneratorCodeForProperty.ts:33` | split into 3 branches; `_uuids` moves into the primitive branch | primary rewrite |
| 2 | `defineSqlSchemaReferenceForDomainObjectProperty.ts:112` | `isReferenceArrayProperty` | rename |
| 3 | `defineSqlSchemaReferenceForDomainObjectProperty.ts:121` | `isPrimitiveArrayProperty` | `_uuids` repair |
| 4 | `isADirectlyNestedDomainObjectProperty.ts:25` | `isReferenceArrayProperty` | rename |
| 5 | `defineDaoUtilCastMethodCodeForDomainObject.ts:31` | `isReferenceArrayProperty` | rename |
| 6 | `defineDaoUtilCastMethodCodeForDomainObject.ts:83` | `isPrimitiveArrayProperty` | `_uuids` repair |
| 7 | `defineDaoFindByMethodCodeForDomainObject.ts:104` | `isReferenceArrayProperty` | rename |

every `isDomainObjectReferenceProperty` call renames alongside. the renames conjoin
`&& isDomainObjectReferenceProperty(x.of)`, which the new guard already implies — inert.

## tradeoffs

- three array kinds, so a three-way branch — the cost of precise column types
- native arrays carry the usual array costs: no element-level foreign keys, whole-value rewrite on
  mutation, membership queries need a GIN index. right for small, read-mostly primitive lists; a
  consumer whose list is large, element-mutated, or queried by membership should hand-model a child
  table. that is also why reference arrays stay relations
- a primitive array flows through the schema property, the cast, and find-by type inference. all
  three must compile and round-trip it, so DAO-wide coherence is the acceptance bar

## edgecases

| edgecase | behavior |
| --- | --- |
| `tags?: string[]` / `string[] \| null` | outer nullable/required kept on the column |
| `photo_uuids: string[]`, matches a dobj | implicit by-uuid relation (unchanged) |
| `favorite_fruit_uuids: string[]`, no matched dobj | `prop.ARRAY_OF(prop.UUID())` (unchanged) |
| `Variant[]`, `type Variant = 'A' \| 'B'` | element hydrates to STRING ⇒ `text[]` |
| `Status[]`, `Status` an enum | native `enum[]` |
| `string[][]` | matches no guard ⇒ fail loud, *"unsupported array shape"* |
| primitive array in a unique key | find-by inference assumes array ⇒ reference and would deref null ⇒ fail loud |

## decisions (settled with the wisher)

1. **native `<primitive>[]`**, not a serialized column — native arrays stay queryable and typed, and
   the schema-generator vocabulary has no `prop.JSON()`
2. **`boolean[]` and `Date[]` are test-covered** — free via `isPrimitiveArrayProperty`, locked by
   data-driven cases
3. **`Date[]` element = `TIMESTAMPTZ`**, inherited from the solo map
4. **primitive array in a unique key = fail loud**; support is out of scope
5. **nested arrays = fail loud**; the `UserInputError` narrows from *"only domain-object arrays"* to
   *"unsupported array shape"*, since the blanket rule no longer holds

no open question blocks. no external research — codegen against local ehmpathy packages.
