```
Error: only arrays of REFERENCEs or UUIDs are supported
  at Object.ARRAY_OF (sql-schema-generator@0.25.3/.../defineProperty.ts:371)
  at .../provision/schema/declarations/sensor.ts:10  (tags: prop.ARRAY_OF(prop.VARCHAR()))
```

verified root cause (read the source at HEAD + the installed 0.25.3 build):

```js
const ARRAY_OF = (property) => {
  const isArrayOfReferences = !!property.references;
  const isArrayOfUuids = serialize(property) === serialize(UUID());
  if (!isArrayOfReferences && !isArrayOfUuids)
    throw new Error('only arrays of REFERENCEs or UUIDs are supported');
  return new Property({ ...property, array: true });
};
```

so `ARRAY_OF` accepts ONLY `REFERENCES(...)` or `UUID()`. `VARCHAR()` / `NUMERIC()` / `BOOLEAN()` /
`TIMESTAMPTZ()` / `ENUM([...])` all fail both checks → throw. and the doc comment reveals the
deeper mismatch: `ARRAY_OF` "create[s] a mapping table ... adds a BINARY(32) column" — it does NOT
emit a native `text[]`/`numeric[]`/`enum[]` column at all. even the `_uuids` case that "works"
produces a join table, not a native `uuid[]`.

- `sql-schema-generator` latest published = `0.25.3` (what we pin); HEAD carries the SAME throw.
- ⇒ NO published version supports native primitive/enum array columns.
