  snapshot of `[32m✔[39m` shows the codes, never the color. cost: a color regression ships with no
  visual diff

  oclif's envelope (an absolute path, a crash dump), which `[t5]` already pins once
- `--help` has no negative row: oclif rejects an unknown flag before the command runs — the
  framework's contract, not this repo's
- `[t4]` is the one test that proves the command idempotent over its own output

## review lanes: four overflowed on one bind shape

four l1 lanes returned `constraint ✋` at i003, each past its context window over 176 files, so each
reviewed no artifact — and a terminal constraint unlocks the next level as though the lane ran.

| bind shape | lanes | outcome |
| --- | --- | --- |
| a brace in the extension slot — `'**/*.{ts,sh,md,snap}'` | r001–r004, r006 | 4 of 5 overflowed |
| repeated flags — `--paths-with a --paths-with b` | r005, r007, r008 | all ran |
| a brace in the directory slot — `'{src,blackbox}/**'` | r009 | ran |

`parseReviewArgs` silently drops an extension-slot brace, so the bind never applied. each overflowed
lane was re-bound to its rubric's own subsystem by a guard edit — strictly more coverage than zero.
r001 `repo-rules` carries the same bind and approved; its scope was left alone, so its verdict was
rendered over an unbounded corpus.

⇒ a narrowed lane that overflows at the same file count as an unnarrowed one has a flag-shape
defect, never a glob-breadth one.
